# Evidence archive

These are the recorded outputs the app reads. **The raw run files are kept exactly as produced**, and their hashes are
verified by the Judge result and by the auditor. Each party's private configuration and journals, local endpoints, the
PayPal Sandbox merchant ID and payer identities are excluded.

| Path | Contents |
|---|---|
| `runs/A2-fresh-1/`, `runs/A2-fresh-2/` | Two fresh seven-party runs recorded on 2026-11-09, shown in the app as `run-1` and `run-2`. Each holds the marketplace intents and matches, contract versions, signed commitments, permits, signed receipts, the full event trace, the Judge result and the model-activity summary. |
| `negatives/` | The 25-case adversarial suite run against live parties: `NEGATIVE_RESULTS.json` (run 2) and `NEGATIVE_RESULTS_run1.json` |
| `paypal_runs/lmf007-20261109T232734Z/` | Customer A's payment: authorization (redacted copy), events, ledger export, readback, readback history |
| `paypal_runs/lmf007-20261109T234414Z/` | Customers B–E: authorization (redacted copy), events, ledger export, four readbacks |
| `PREREGISTRATION_FRESH_2.json`, `FREEZE_BEFORE_FRESH_1.json` | Expected Judge checks and scorer hashes, frozen **before** each fresh run |
| `COUNTERFACTUAL_A0_A1_A2_A3.json` | Baselines: each buyer alone, known peers, discovery plus federation (including the failed attempts of 2026-11-07), and a central matcher |
| `PAYPAL_AUTHORITY_PREFLIGHT.json`, `OLD_HOLDS_RECONCILIATION_READ_ONLY.json`, `LICENSE_GATE.json` | **Historical gate readings from 2026-11-09, taken before any payment was authorized.** They are kept as a record and do not describe the current payment status. |
| `dossier/`, `UI_PROVENANCE_AUDIT.json`, `NEGATIVE_TESTS.json`, `ECONOMIC_CASE.json`, `HYPOTHETICAL_BREAK_EVEN.json`, `PAYMENT_NEGATIVES.json` | Generated by `scripts/build_and_serve.py` and `scripts/run_payment_negatives.py`. They are rebuilt and checked in CI. |

**Run names.** The directory names `A2-…` and `lmf007-…` are the identifiers recorded at run time, and they are kept so
that hashes and journal references stay valid. `A2` is the discovery-plus-federation arm of the experiment design.
